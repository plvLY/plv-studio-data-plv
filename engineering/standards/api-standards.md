# API 与开发规范

接口与代码规范的作用是降低协作成本，让不同时间、不同执行者写出的代码保持一致。

## 接口约定

### 命名

- 资源使用名词复数，例如 `/projects`、`/documents`
- 路径使用小写字母与连字符
- 行为通过 HTTP 方法表达，不在路径中重复动词

### 请求与响应

- 请求参数与响应字段保持同名
- 响应结构稳定，字段增减不影响已有调用方
- 错误响应包含可读的错误信息与稳定的错误码

### 版本

对外接口发生不兼容变更时，通过版本区分，不直接修改已发布行为。

## 代码规范

- 一个模块只承担一类职责
- 公共逻辑提取前先确认确实被复用
- 错误处理集中在边界，不在每一层重复捕获
- 注释解释「为什么」，不复述「做了什么」

## 数据校验

- 外部输入必须校验
- 内部调用信任框架与类型保证
- 校验失败时给出具体字段与原因

## 变更原则

- 先读代码再修改
- 修改范围与需求直接相关
- 不为假设中的未来需求提前设计
