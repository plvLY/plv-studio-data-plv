# 数据结构与内容规范

数据结构规范的目标是：**内容可以持续增长，而页面结构不需要反复修改**。

## 基本原则

### 数据与展示分离

- 数据仓库负责内容与结构
- 框架仓库负责读取、校验与渲染
- 页面组件不依赖某篇具体文档的文件名或正文结构

### 契约先行

所有 JSON 都包含版本号，并通过 Schema 校验。字段、枚举与必填项在构建阶段检查，而不是等到页面出错。

### 标识稳定

`id` 与路径一旦发布就保持稳定。重命名会导致链接失效，应通过新增内容替代。

## 内容元数据

| 字段 | 说明 |
| --- | --- |
| id | 内容唯一标识 |
| title | 内容标题 |
| category | 所属分类 |
| summary | 内容摘要 |
| path | 内容文件路径 |
| status | 发布状态 |
| featured | 是否精选 |
| order | 展示排序 |
| updatedAt | 最近更新时间 |

## 状态约定

- `draft`：草稿，不公开展示
- `published`：已发布，允许公开展示
- `archived`：已归档，不进入常规列表

页面默认只读取 `published` 内容。

## 校验要求

- 缺失字段、错误分类、无效路径在构建阶段报错
- 重复 id、重复排序值在构建阶段报错
- 跨文件引用需要检查是否存在
