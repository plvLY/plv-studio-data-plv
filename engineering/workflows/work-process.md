# 工作流程

工作流程描述 PLV Studio 如何组织、规划和推进工作。它关注的不是某个项目具体怎么做，而是**所有项目共享的推进方式**。

## 适用范围

- 新需求的接收与判断
- 多任务并行时的优先级安排
- 阶段成果的检查与复盘

## 四个环节

### 1. 目标与需求确认

在开始任何实现之前，先回答三个问题：

- 要解决的是什么问题
- 交付边界在哪里
- 用什么标准判断完成

目标不清晰时，不进入实现阶段。宁可先补一次需求澄清，也不要用代码试探方向。

### 2. 任务拆解与规划

把目标拆成可以独立验收的小任务，并明确：

- 任务之间的先后顺序与依赖
- 每个任务的产出物
- 哪些任务可以并行

拆解的标准是：每个任务都能用一句话说明「做完是什么样」。

### 3. 执行与过程管理

执行阶段保持两件事：

- **状态可追溯**：当前在做什么、完成了什么、卡在哪里，都有记录
- **范围可控**：新增需求先进入待办，不直接插入当前任务

过程记录不追求完整日志，但关键决策要留下原因。

### 4. 成果检查与复盘

完成后对照验收标准逐项检查，并复盘：

- 哪些判断被验证是对的
- 哪些问题本可以更早发现
- 哪些经验值得沉淀为方法或规范

复盘结论进入工程模块，而不是只留在个人记忆里。

## 与其他分类的关系

工作流程回答「怎么推进」，开发流程回答「项目怎么走完」。前者作用于所有工作，后者作用于单个项目。
