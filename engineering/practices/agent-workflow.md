# Agent 工作流设计

Agent 适合承担边界清晰、可验证的执行任务。工作流设计的核心是**明确输入、约束与检查点**。

## 基本结构

1. **定义任务**：说明目标、范围和完成标准
2. **提供上下文**：给出相关文件、约定和限制
3. **执行**：由 Agent 在边界内完成任务
4. **检查**：由人或自动校验确认结果
5. **记录**：保留关键决策与变更

## 设计原则

### 任务要可验证

每个 Agent 任务都应能用具体条件判断是否完成。无法验证的任务，先拆成可验证的部分。

### 边界要明确

明确哪些文件可以改、哪些不能改、哪些操作需要确认。边界越清晰，返工越少。

### 保留人工检查点

高风险操作、结构性改动和对外发布，必须保留人工确认环节。

### 上下文要新鲜

优先让 Agent 读取当前真实状态，而不是依赖对话中的旧描述。

## 反模式

- 用模糊指令期待 Agent 自行理解目标
- 一次授予过大的改动范围
- 跳过验证直接接受结果
- 让 Agent 在缺少上下文时猜测约定
