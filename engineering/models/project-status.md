# 项目状态模型

项目状态模型用有限的状态描述项目整体所处的位置，避免用模糊的描述判断进度。

## 状态定义

| 状态 | id | 含义 |
| --- | --- | --- |
| 规划中 | `planning` | 目标与方案尚未确定，未进入实现 |
| 开发中 | `developing` | 正在实现，尚未进入系统验证 |
| 验证中 | `validating` | 功能已完成，正在做系统验证 |
| 已交付 | `delivered` | 已完成约定开发与交付内容 |
| 运行中 | `running` | 已交付并处于稳定运行状态 |
| 持续迭代 | `iterating` | 已交付后仍在持续维护与更新 |
| 已归档 | `archived` | 不再维护，仅保留记录 |

## 状态与阶段的关系

状态回答「项目整体怎么样」，阶段回答「项目走到哪一步」。

- 一个项目只处于一个当前状态，阶段可以与之并行推进
- 「已交付」不等于流程结束，运行与迭代阶段仍可能继续
- 「已归档」表示停止维护，不代表内容被删除

## 状态计数口径

项目模块的概览统计中，每个项目只有一个当前主状态：

- 总数：非归档的公开项目
- 开发中：`developing` 与 `validating`
- 已交付：`delivered`、`running` 与 `iterating`，即已完成约定开发与交付内容的项目
- 持续迭代：`iterating`，是「已交付」的子集，表示已交付后仍在维护或更新
- 已归档：`archived` 单独统计，不计入总数

## 使用原则

- 状态必须能从项目记录中得到解释
- 状态变更应伴随时间点与原因
- `delivered` 与 `running` 必须填写交付日期
- 不使用「差不多完成」「基本可用」这类无法验证的描述
