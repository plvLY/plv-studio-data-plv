# 交付形态模型

交付形态模型用于区分项目最终以什么形式被使用，从而决定验收方式和运行成本。

## 六种形态

| 形态 | id | 说明 | 关注点 | 验收 |
| --- | --- | --- | --- | --- |
| Web 部署应用 | `web_deployment` | 构建后部署到托管平台，持续可访问 | 构建稳定性、内容正确性、加载性能 | 页面可访问、链接有效、构建可复现 |
| 本地运行软件 | `local_application` | 安装或克隆后在本地运行 | 安装流程、运行环境、数据落地 | 目标环境可安装运行、数据可读写 |
| Agent / API 服务 | `agent_api` | 通过接口或对话被调用的能力 | 输入输出契约、错误处理、鉴权 | 契约稳定、异常可恢复 |
| 软件包 | `software_package` | 可安装、可分发的成品包 | 打包体积、依赖声明、卸载清理 | 可安装、版本可追溯 |
| 源代码 | `source_code` | 以源码与可复现构建流程交付 | 代码结构、构建可复现、文档 | 克隆后可完整构建 |
| 其他 | `other` | 以上都无法准确描述 | 按实际情况说明 | 按实际情况说明 |

## 使用方式

1. 先确定交付形态，再选择验收标准
2. 在项目详情页的「交付形态」段落记录形态与说明
3. 需要外部访问时，在交付入口中列出线上地址或源码地址

不同形态的项目不应套用同一套质量门槛；同一项目只对应一种形态，混合交付需要在说明中写清主形态。
