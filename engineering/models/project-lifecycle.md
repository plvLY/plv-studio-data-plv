# 项目生命周期模型

项目生命周期模型把项目从想法到稳定运行的过程抽象为六个阶段，用于统一判断项目当前所处的位置。

## 阶段

阶段顺序固定，不可调整；每个项目都完整记录六个阶段。

| 阶段 | id | 关注点 | 典型产出 |
| --- | --- | --- | --- |
| 需求分析 | `requirements` | 目标、范围与可行性 | 需求说明、验收标准 |
| 方案设计 | `design` | 结构、方案与取舍 | 架构说明、技术决策 |
| 开发实现 | `development` | 实现与自测 | 可运行版本 |
| 测试验证 | `testing` | 质量与缺陷 | 测试记录、问题清单 |
| 交付验收 | `delivery` | 上线与确认 | 发布版本、验收记录 |
| 运行与迭代 | `iteration` | 观察与迭代 | 维护记录、改进项 |

## 阶段状态

| 状态 | 含义 |
| --- | --- |
| `completed` | 阶段目标达成，产出物已确认 |
| `in_progress` | 阶段进行中，全项目至多一个 |
| `pending` | 尚未开始 |
| `skipped` | 有意跳过，不适用于本项目 |
| `not_applicable` | 本项目不需要该阶段 |

`applicable` 为 `false` 时状态只能是 `skipped` 或 `not_applicable`。

## 进度口径

阶段进度 = 已完成的适用阶段数 ÷ 全部适用阶段数。

- 分母只统计 `applicable` 为 `true` 且状态不是 `skipped` / `not_applicable` 的阶段
- 分子只统计 `completed` 的阶段
- 一个项目可以没有适用阶段，此时进度记为 0%

## 使用方式

1. 判断项目当前处于哪个阶段
2. 检查该阶段的产出物是否存在
3. 决定是否可以进入下一阶段

## 边界说明

- 阶段不等同于工期，小项目可以在同一天内跨越多个阶段
- 不适用的阶段要显式标记为 `skipped` 或 `not_applicable`，不能留空
- 归档不是失败，而是项目进入只读状态的正常选择

## 与项目模块的关系

项目模块记录每个项目的阶段状态与进度；本模型只定义阶段本身，不记录具体项目数据。
